# plugin/hooks/ — the session-start alert hook and the /whispr-graph pane

What it does: `hooks.json` declares two things. The **SessionStart hook** (`session_start.py`): when a session starts or resumes, it shows whispr's open alerts in one short line (`systemMessage`, and the same line as context for Claude), adds the graph-first note to Claude's context only (`graph_first_note`, P2b: use whispr-kg first and cite its quote; on unless `WHISPR_GRAPH_FIRST_NOTE` is `off`), shows nothing when neither applies, and never blocks or fails a session (exit 0 always, database read bounded by `alerts.session_start.timeout_s`). The **pane mod** (`graph.tsx`): `/whispr-graph [NAME]` opens a pane on the knowledge graph around a person, project or topic (`python -m kg.view`, read-only).
How to run it: the plugin loads both itself. The hook runs in exec form on the plugin's `python` option (`"command": "${user_config.python}"`, `"args": ["-s", ".../session_start.py"]`): never the python on PATH, never a shell. It finds whispr from the `whispr_root` option (exported to it as `CLAUDE_PLUGIN_OPTION_WHISPR_ROOT`), else the folder above the plugin, and the overlay from the `config` option (`CLAUDE_PLUGIN_OPTION_CONFIG`). With no whispr install there it prints one short line saying so, never nothing. By hand: `python -m pipeline alerts --session-start` prints the same line.
Tests: the hook, `.venv\Scripts\python.exe -m unittest discover -s tests -p "test_pipeline_alerts.py" -v` (malformed stdin, no alerts, alerts, broken database, the options, `..` and sensitive paths refused, the note on, off and after alerts); the pane, `claude plugin test plugin` (`plugin/tests/graph.test.ts`, with kg.view faked).
Config keys read: `alerts.session_start.*` (count, length, timeout), `graph_first_note.*` (the note, its switch); through kg.view, `kg.view.*` and `kg.traverse.*`; plus what `kg/` reads to open the database. Plugin options read: `python`, `whispr_root`, `config`, `graph_max_hops`, `graph_timeout_s`.

The hook follows the five hook-security rules: stdin parsed in try/except with fields null-checked; no shell; the two paths it takes from its environment refused on `..`, resolved, and checked to be a whispr install whose module loads from under it; absolute paths; no sensitive file. The path checks live in `../lib/whispr_paths.py`, shared with `../bin/pipeline.py`, and `session_start.py`'s docstring says how each rule is met. `hooks.json`'s `timeout` (seconds) must exceed `alerts.session_start.timeout_s` plus interpreter start-up.
